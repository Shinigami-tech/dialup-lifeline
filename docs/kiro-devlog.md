# Kiro dev log (raw notes for the "How we used Kiro" write-up)

## Day 1 (2026-11-11)
- Wrote 3 specs (modem-core, mesh-relay, lifeline-app) in EARS format, 4 steering docs (product, tech, structure, modem-dsp with fileMatch on src/modem/**), 3 agent hooks.
- Migrated hooks to the new PostFileSave JSON format.
- Task 1 (CRC-16/X.25): Kiro implemented table-driven CRC + 12 tests incl. 2 fast-check properties (round trip, every single-bit flip detected, 2000 runs). The DSP hook fired on save and ran the suite. Kiro self-corrected the residue constant (0x0F47 vs 0xF0B8, byte-order) by writing a probe script. ~2.1 credits.
- Task 2 (HDLC + NRZI): the round-trip PROPERTY TEST found a real bug: the leading 0 of a closing 0x7E flag leaked into the payload. Kiro traced it bit by bit and redesigned the deframer with a `pendingZero` lookahead. 27 tests passing, 500-run round-trip properties over random 0-255-byte payloads. ~4.8 credits.
  -> Story for judges: PBT caught a bug unit tests with fixed vectors missed.
- Task 3 (AFSK modulator): continuous-phase FSK with phase accumulator, float samplesPerBit with rounded bit boundaries (no drift), 5 ms ramps; 10 tests incl. fast-check properties (length invariant, amplitude bounds, continuous-phase bound 2A·sin(π·fmax/fs)). fast-check caught that fc.float needs 32-bit bounds. ~1.9 credits.
- Task 4 (demodulator + PLL): hardest task (~27 min, ~10.6 credits). Kiro wrote dozens of probe scripts, found (a) a sliding-DFT phase bug where the reference phasor was keyed to absolute time, and (b) the causal-window W/2 delay of zero-crossings. Switched to a delay-domain correlator (37 MACs/sample at 1200 baud) with PLL nudging toward crossings at phase 0.5. 48 tests pass incl. round-trip over random payloads, sample rates, amplitudes and ±2% clock skew.
Total so far ~19.5 of 50 free credits; 4 of 8 modem-core tasks done.
- Task 5 (full noise/skew property test): first version passed but was VACUOUS - it modulated at rxRate*skew then resampled back, cancelling the skew. Human review + an end-to-end loopback probe showed a 50-byte SOS fails at 1-2% skew. Fed the finding back to Kiro: it rewrote P3 with the correct model (TX believes rxRate, DAC runs at rxRate*skew), confirmed it failed, then upgraded the PLL to second order. A gain sweep (56 cases) exposed the real root cause: the integrator sign was inverted (err>0 = clock fast => bias must decrease). After the fix: 52/52 tests green, 56/56 sweep cases at +-2% skew with noise. Lesson: PBT is only as good as the model inside the property.
- Also built the first UI prototype (CRT terminal, HELP/SAFE, status chips, people counter, live oscilloscope, mic listening via AudioWorklet).
- UI tasks 1-7 of lifeline-app (PWA + service worker, 6 languages, SOS builder, inbox with distance/bearing, Rescue Mode with radar + urgency triage + auto-ACK + on-the-way/resolved, CRT + high-contrast theme, Drill mode) were implemented by hand while waiting for hackathon credits; Kiro tasks for mesh relay and the binary packet remain. Message codec has a fast-check round-trip property (300 runs) and an end-to-end test that sends a real SOS through the modem with 1% clock skew and noise. 57 tests green.


## Day 2-3 (2026-11-12/13)
- modem-core tasks 6-8 (Kiro): AudioWorklet receiver + diagnostics counters, robust 300-baud mode (property: at least as noise tolerant as 1200 baud at 6 dB SNR), classic dial-up screech synth (skippable, frame still decodes after it).
- mesh-relay tasks 1-6 (Kiro, ~20 credits): 17-byte bit-level packet with round-trip property; 24 h dedup store + IndexedDB adapter; relay scheduler (2-8 s random delay, suppression); listen-before-talk + RX mute while TX; ACK flow with resend backoff; mesh simulator with the property "every SOS reaches each phone in its connected component exactly once".
- Kiro then wired the relay into the app (src/mesh/msg-relay.ts glue, "Relay SOS for others" setting in 6 languages).
- End-to-end test with 3 real browsers on the live site (sender -> relay phone -> rescuer, real AFSK audio through fake microphones) found 2 bugs the unit tests missed: (1) the sender's own second copy of a packet cancelled the relay phone's rebroadcast (suppression must only trigger on a copy at >= our hop); (2) the sender relayed the ACK addressed to itself. Fed back to Kiro: it reworded Requirement 2.2, added properties for both, fixed them. 150 tests green in 16 files; deployed to dialup-lifeline.vercel.app.
